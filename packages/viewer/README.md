# Evidence viewer

The viewer is a static, read-only human projection of an accepted Agent-first evidence contract. It refuses to present a result unless the scenario pointer names an accepted manifest, the manifest reports `accepted`, the technology profile matches the scenario, and the layered resolver passes.

Serve the repository root with `make viewer`, then open the scenario page through the address printed by the server. The viewer uses the Cortrix Magma Orange visual identity, official Cortrix logo assets, responsive light/dark themes, a scenario-level Technology Profile, and an Agent Execution Path. Evidence-derived values use DOM text nodes and are never evaluated as code or unsanitized HTML.

For a local review before promotion, run `make viewer-candidate-qa RUN_ID=<run_id>`. The server validates one ignored `.runs/` candidate and exposes a separate, temporary `/packages/viewer/candidate-qa.html` route. The page requires `state=candidate`, `screenshot_eligible=false`, `human_review_required=true`, no acceptance metadata, passing assertions, and matching evidence identity. It is visibly labeled as Candidate QA. Its browser captures are review artifacts, cannot be registered by `record-screenshot`, and do not satisfy the accepted screenshot contract.

The DeepSeek Harness scenarios use a second accepted-only projection because their comparison contract differs from the original layered-ranking scenario. Start it with `make viewer-harness SCENARIO=database-change-conflict-guardian` or `make viewer-harness SCENARIO=api-version-drift-coding-agent`. The server refuses a missing, candidate, unreviewed, or identity-mismatched run before it serves `/packages/viewer/harness.html?scenario=<scenario-id>`. The page shows the same question, controlled variable, Run A negative control, Run B plugin result, application resolver, provider usage, source identity, cleanup, and independent Clean Room review from tracked accepted evidence.
